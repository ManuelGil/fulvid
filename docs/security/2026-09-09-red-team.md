# Adversarial review, 2026-09-09

Historical evidence from a completed campaign against Fulvid 0.1.0 on Linux x64. The standing contract is [SECURITY-AND-RESILIENCE.md](../SECURITY-AND-RESILIENCE.md). Findings marked Fixed were corrected in that same cycle. This file is not the current control list.

Adversarial review of Fulvid: boundary red team, filesystem and data-loss
attacks, resource exhaustion, artifact inspection, and supply chain.

Every entry below was reproduced by running an attack, not by reading code. An
attack that failed to break anything is recorded under [Coverage](#coverage), not
as a finding. Findings are separated by kind, because "slow" and "exploitable"
are not the same claim:

| Kind                    | Meaning                                                              |
| ----------------------- | -------------------------------------------------------------------- |
| **Vulnerability**       | A trust boundary was crossed: containment escape, execution, disclosure |
| **Robustness defect**   | Ordinary conditions made the app fail or lose usable state             |
| **Performance problem** | Bounded work became unbounded; a local denial of service              |
| **Known limitation**    | A property the current architecture cannot provide                     |
| **Residual risk**       | A real risk that survives the fixes                                    |

Scope: `src/bun` (privileged host), `src/mainview` (renderer), `packaging/`,
`.github/workflows`, and the built Linux artifacts. Audited at version 0.1.0.

## Result

**No vulnerability was found.** Folder containment, MDX inertness, Preview
escaping, grant handling, and RPC validation all held under every attack. The
five findings are two robustness defects, two performance problems, and one
packaging defect. All five are fixed, each with a regression test, and each
attack was re-run afterwards.

| ID                | Kind                | Severity | Component            | Status |
| ----------------- | ------------------- | -------- | -------------------- | ------ |
| [F-01](#f-01)     | Performance problem | High     | Preview / HTML Export | Fixed  |
| [F-02](#f-02)     | Robustness defect   | Medium   | Folder scan          | Fixed  |
| [F-03](#f-03)     | Robustness defect   | Medium   | Folder scan          | Fixed  |
| [F-04](#f-04)     | Performance problem | Medium   | Link resolution      | Fixed  |
| [F-05](#f-05)     | Packaging defect    | Low      | Linux `.deb`         | Fixed  |

## F-01

**A document freezes the renderer for a minute through Preview or HTML Export**

- **Kind:** Performance problem (local denial of service)
- **Severity:** High
- **Component:** `src/mainview/modules/editor/markdown/markdownPreview.ts`
- **Preconditions:** A document with dense inline Markdown is open. Preview
  enabled reaches it while typing; **HTML Export reaches it with Preview off**.

### Attack

Fill a document to the existing 200,000-character Preview cap with inline links,
then render one Preview frame.

```markdown
[l](n0.md) [l](n0.md) [l](n0.md) ...   // 18,181 links, 199,991 characters
```

### Observed

```text
chars=199991 links=18181 (at the 200000 preview cap)
single preview render: 66.2s
```

66.2 seconds for one frame, on a 140 ms typing debounce, on the renderer's only
thread. Export HTML calls the same renderer synchronously, so a document reaches
this with the Preview pane closed.

### Expected

A document is data. Opening or exporting one is bounded work.

### Root cause

Upstream, not Fulvid. `marked` 18.0.12's inline lexer is quadratic in the number
of inline constructs. Stock `marked` with no custom renderer reproduces Fulvid's
curve exactly:

| inline constructs | Fulvid render | stock `marked` |
| ----------------- | ------------- | -------------- |
| 1000              | 299 ms        | 289 ms         |
| 2000              | 934 ms        | 972 ms         |
| 4000              | 3370 ms       | 3508 ms        |
| 8000              | 13335 ms      | 13289 ms       |

Plain prose is linear (8000 words = 241 ms); links, emphasis, code spans,
images and autolinks are all quadratic. 18.0.12 is the current release, so
there is no upgrade to take.

The character cap measures the wrong dimension: cost tracks inline-markup
density, not length.

### Fix

`PREVIEW_INLINE_MARKUP_LIMIT` (2000) alongside the existing character cap, with
one linear counting pass that stops early. Over the ceiling, Preview and Export
show the source escaped and inert, and say so - the same way the character cap
already degrades. Export reports it too, so a degraded export is never silent.

Fulvid cannot fix `marked`'s tokenizer, and moving rendering off-thread would be
an architectural change for a bound that a ceiling already provides.

### Verification

| | before | after |
| --- | --- | --- |
| 18,181 links at the character cap | 66.2 s | **4 ms** |
| Export HTML, 18,000 links | 66 s | **2 ms** |

Headroom checked against every Markdown file in the repository: the densest
(`docs/I18N.md`) has **184** markers against a ceiling of **2000**. Synthetic
heavy prose (300 heading/bold/italic/link/code paragraphs, 1800 markers) still
renders normally.

### Regression

`tests/mainview/modules/editor/markdown/markdownPreview.unit.test.ts` -
"inline markup density". Asserts elapsed time, not just the flag, so a
regression to quadratic fails the test.

## F-02

**One unreadable subdirectory makes the whole folder fail to open**

- **Kind:** Robustness defect
- **Severity:** Medium
- **Component:** `src/bun/filesystem/scanning/scanDirectory.ts`

### Attack

```text
folder/readable.md
folder/denied/        (chmod 000)
```

Open the folder.

### Observed

```text
THREW EACCES: permission denied, scandir '.../folder/denied'
```

The scan threw. No documents opened, though `readable.md` was fine. Reachable
without an attacker: a root-owned directory, a stale mount, a `.Trash`.

### Expected

Read what is readable; report what was not.

### Root cause

`readdir` in the walk was unguarded, so any `EACCES` aborted the whole scan.

### Fix

Unreadable entries are skipped and counted (`skipped`), surfaced in EN/ES next
to the existing partial-scan notice, so a partial folder is never silent.

### Verification

Re-ran the attack: `held  hostile:unreadable-directory  ok 0 notes` - the scan
returns instead of throwing.

### Regression

`tests/bun/filesystem/scanning/scanDirectory.integration.test.ts` -
"an unreadable subdirectory is skipped, not fatal". That case injects a
skippable `EACCES` at the walk catch so Windows CI cannot hide behind
`chmod(000)`, which does not deny access there. A POSIX-only extra still
uses real mode bits where the kernel enforces them. The finding itself is
unchanged: production already skipped the subtree.

## F-03

**A document removed or locked mid-scan makes the whole folder fail to open**

- **Kind:** Robustness defect
- **Severity:** Medium
- **Component:** `src/bun/filesystem/scanning/scanDirectory.ts`

### Attack

Create 200 documents, start a scan, delete half of them while it runs.

### Observed

```text
THREW ENOENT: no such file or directory, statx '.../folder/v0.md'
```

A file listed by the walk and gone by the analysis pass aborted the scan. This
is ordinary: a sync client, a `git checkout`, or a branch switch during a scan.

### Expected

The folder is a live filesystem, not a snapshot. Analyse what is still there.

### Root cause

The analysis loop had no per-file error handling, so one vanished file threw out
of `scanWorkspace`.

### Fix

Same skip-and-count path as F-02, applied to the analysis pass.

### Verification

Re-ran the attack: `held  hostile:file-vanishes-during-scan  ok 101 notes`.

### Regression

Two tests in the same file: a deterministic one (the listed document is
removed before analysis, asserting `skipped === 1`) and a concurrent one
asserting the scan never throws. The deterministic case is the F-03
condition itself (`ENOENT` after listing), not `chmod(000)`, because
Windows mode bits do not deny the later `stat`. A POSIX-only extra still
uses real mode bits where the kernel enforces them. The concurrent case
asserts only guaranteed invariants - an earlier version of it asserted a
fixed total and was flaky 1 run in 5, which is a defect in a regression
test, not evidence of one.

## F-04

**Link resolution is quadratic in folder size**

- **Kind:** Performance problem (local denial of service)
- **Severity:** Medium
- **Component:** `src/mainview/modules/document/links/linkSemantics.ts`

### Attack

Resolve folder-wide edges (Graph page, Document Context, reference counts) for
folders of increasing size, 10 links per document.

### Observed

| documents | before    |
| --------- | --------- |
| 100       | 48 ms     |
| 250       | 222 ms    |
| 500       | 725 ms    |
| 1000      | 2752 ms   |
| 2000      | 10707 ms  |

Clean O(n^2). The folder scanner permits `MAX_SCANNED_DOCUMENTS = 5000`, so a
folder Fulvid will happily open projects to roughly a minute of frozen renderer
on the Graph page.

### Expected

Opening the Graph for a folder Fulvid agreed to scan is bounded work.

### Root cause

`resolveDocumentPath` scanned the whole note list on every call - `notes.find`
for the exact path, a full rebuild of the stem map, then `notes.find` again for
aliases and for titles. Called once per link, that is O(links * notes).

### Fix

Lookup tables (path, stem, alias, title) built once per scanned-notes array and
memoised in a `WeakMap` keyed on that array. A rescan produces a new array, so
the index invalidates on its own with nothing to clear by hand.

The maps preserve the previous semantics exactly, including "first note wins" on
duplicates and the indexing of empty normalised keys, which `notes.find` matched.

### Verification

| documents | before   | after     |
| --------- | -------- | --------- |
| 1000      | 2752 ms  | **32 ms** |
| 2000      | 10707 ms | **57 ms** |

188x at 2000 documents, and linear. Memory across 40 open/resolve/render/close
cycles is flat (2, 4, 3, 3, 3 MB), so the memoisation does not retain folders.

### Regression

`tests/mainview/modules/document/links/linkSemantics.unit.test.ts` -
"resolution scale": asserts the cost shape, that all four resolution routes
still land on the same note, that duplicates still resolve first-wins, and that
a rescan is not answered from the previous folder's index.

## F-05

**The Linux package ships the build machine's private directory mode**

- **Kind:** Packaging defect
- **Severity:** Low
- **Component:** `packaging/linux/deb.sh`

### Attack

Build the `.deb` and inspect the archive's root entry.

### Observed

```text
drwx------ root/root  0  ./
```

Extracting it produces a `0700` root:

```console
$ dpkg-deb -x fulvid_0.1.0_linux-x64.deb out/ && stat -c '%a' out/
700
```

### Expected

A package declares its modes. It does not carry the builder's umask.

### Root cause

`stage="$(mktemp -d)"` is `0700`, and `dpkg-deb --build` records the staging
root as the package's `./` entry.

### Impact

Scoped honestly: `dpkg -i` does not apply the archive's root entry to `/`, so
this is **not** a way to chmod a system root. What it does affect is anything
that extracts the package - inspection, repackaging, container image builds -
which lands a directory only its owner can enter. It is also a reproducibility
defect: the artifact records a property of the build environment.

The rest of the package audited clean: no maintainer scripts (nothing executes
on install), all files `root:root`, no setuid/setgid, nothing world-writable,
two executables (`/usr/bin/fulvid`, `/opt/fulvid/bin/launcher`).

### Fix

`chmod 755 "$stage"` after `mktemp -d`. The gpg homedir in
`packaging/linux/lib.sh` keeps `0700` deliberately - gpg requires it.

### Verification

Rebuilt: `drwxr-xr-x root/root 0 ./`, extraction mode `755`.

## Coverage

Attacks that ran and did **not** break anything. Recorded so the next audit
knows what was already tried, not presented as findings.

### Preview, HTML Export, MDX - 168 payload classes times 2 surfaces

336 rendered outputs parsed with a real HTML tokenizer (Python `html.parser`)
and checked for active elements, `on*` handlers, dangerous URL schemes, and
remote-fetching attributes. **0 findings.**

Covered: `<script>` (plain, split, remote), event handlers, SVG/MathML mutation
XSS, `<iframe>`/`srcdoc`, `<object>`, `<embed>`, `<form>`, `<base>`,
`meta refresh`, remote stylesheets, `<style>`, style attributes, `noscript` and
`template` mutation, comment breaking, CDATA, `xmp`; `javascript:` in plain,
case-varied, entity-encoded, tab-, newline- and NUL-separated forms, plus
`data:`, `vbscript:`, `file:`, `blob:`, `about:`, `views://`, protocol-relative
and reference-definition delivery; attribute breakout through link titles, alt
text, labels and heading IDs; MDX imports, exports, expressions, components,
nested JSX, dynamic import and fragments; RTL/zero-width/fullwidth obfuscation
and entity double-encoding; deep nesting, bracket bombs and unclosed constructs.

The scanner was validated against positive controls first - 9 known-bad inputs
detected, 1 known-good passed - so "0 findings" reflects the renderer, not a
broken detector.

MDX is escaped and marked inert, never mounted. Images are replaced with inert
placeholders, so a document causes no network request. External links are
limited to `https:` and `mailto:`; everything else renders `#`.

### Filesystem - 68 attacks

**0 escapes.** Every traversal form refused (`../`, `..\\`, percent-encoded,
absolute POSIX/UNC/drive-letter, mixed separators, NUL-embedded, fullwidth and
fraction-slash homoglyphs, whitespace-padded, 40-deep, 300-character segments)
across read, write, create, rename and delete.

Symlink escape refused for directory links, symlink chains, file links and
relative links, on read, write, create, delete, directory listing and scan. The
file outside the folder was byte-identical afterwards in every case.

TOCTOU: replacing a document with a symlink after it was opened, and replacing a
directory with a symlink after the folder was authorised - both refused.

Data loss: external modification produced a conflict rather than an overwrite;
12 concurrent creates of one name produced exactly one winner and an unblended
file; concurrent 200 KB writes left pure content, never interleaved; no
temporary files survived; a target replaced by a directory was refused.

Grants: forged, empty and traversal-shaped tokens all refused; a grant for a
non-Markdown path refused the write.

### RPC boundary - 4290 validator calls, 264 io calls

**0 uncontrolled errors from the validators**, and no prototype pollution from
`__proto__` or `constructor.prototype` payloads. Hostile values (`null`,
`undefined`, `NaN`, `+/-Infinity`, throwing `toString`/`valueOf`, symbols,
functions, `Map`/`Set`/`Date`/`RegExp`, 1 MB strings, lone surrogates,
null-prototype objects) were passed both as the whole parameter object and in
every field position.

Calling the io layer *directly* with non-string content does raise a host
`TypeError`, but that is not reachable through the boundary: handlers validate
first, and `containHostError()` converts anything unexpected into
`fulvid.fs:operationFailed`. Verified explicitly - a `TypeError` carrying
`/home/me/secret` crosses as `fulvid.fs:operationFailed`, leaking neither the
path nor the internals.

### Search, Graph, memory

Search is linear and result-capped (5000 documents, 5 ms). Dense graphs (one
document linking to every other) are linear. Symlink cycles terminate (1 ms) -
the walk treats symlinks as neither file nor directory. Forty
open/resolve/render/close cycles leave the heap flat.

### Artifacts and supply chain

The Linux tarball contents were inventoried: no source maps, no `.env`/key/
certificate files, no secret-shaped strings, and no build-machine absolute paths
in the shipped JavaScript or HTML. The CSP reaches the packaged page intact.
The packaged launcher was executed and started cleanly.

All 7 distinct GitHub Actions are pinned to full commit SHAs with version
comments. No piped-shell installs in build or packaging scripts. The `.deb` has
no maintainer scripts.

## Known limitations

**A compromised renderer can call every RPC handler.** Electrobun's preload
exposes the bridge to page scripts; that is the framework's design, not
something Fulvid configures. This is precisely why authority lives in the host:
handlers validate every parameter, folder roots are approved only through a
native dialog, and containment is re-checked canonically. The renderer's
capability is bounded by what the handlers allow, not by the bridge.

**Content Security Policy is partial.** `object-src`, `frame-src`, `base-uri`
and `form-action` are set to `'none'`. `script-src`, `style-src`, `img-src` and
`worker-src` are deliberately unset: Vite HMR injects inline module scripts,
Monaco 0.56 injects `<style>` at runtime, and whether `'self'` resolves for the
`views://` scheme across WKWebView, WebView2 and WebKitGTK has not been verified
in a packaged run on each platform. A policy that merely allows `'unsafe-inline'`
would buy nothing. Document content is kept inert by escaping, verified above,
not by the CSP. See the comment in `src/mainview/index.html`.

**Check-then-write remains non-atomic** between the mtime check and the rename
in `writeDocument`. Closing it needs `openat`/`O_NOFOLLOW`, which Bun does not
expose. The window is narrow and the mtime check is the guard; concurrent
creation is already atomic via exclusive create.

## Residual risks

1. **Documents just under the density ceiling still cost up to ~1 second** to
   render, and a single 200,000-character line with no markup at all costs
   ~1.6 s. Both are bounded - by the density ceiling and by the character cap
   respectively - and rare: the densest file in this repository uses under a
   tenth of the density ceiling. Neither is free. Both shrink if `marked`'s
   inline lexer becomes linear.
2. **`marked` remains an upstream quadratic dependency.** The ceiling bounds the
   consequence; it does not remove the cause. Revisit the ceiling on any `marked`
   upgrade.
3. **Windows and macOS were not attacked.** This audit ran on Linux x64. Junction
   and reparse-point containment, and the packaged runtime on those platforms,
   are covered by CI compatibility workflows but were not red-teamed here.
4. **The `0700` staging mode was a build-environment property that reached an
   artifact.** One instance is fixed; packaging scripts should keep declaring
   modes explicitly rather than inheriting them.

## Recommendations

Not findings - judgement calls for later.

1. Track `marked` for a linear inline lexer, then reconsider
   `PREVIEW_INLINE_MARKUP_LIMIT`.
2. Verify a stricter `script-src`/`worker-src` in a packaged run on each
   platform, then tighten the CSP for packaged builds.
3. Red-team junctions and reparse points on Windows against the same containment
   suite.

## Reproducing

The attack harnesses were written for this audit and are not committed - they
depend on a scratch sandbox and take minutes to run. What is committed is the
regression coverage each finding earned:

```bash
bun test .unit.test.ts          # includes F-01, F-04 regressions
bun test .integration.test.ts   # includes F-02, F-03 regressions
bash packaging/linux/deb.sh     # F-05: inspect the "./" entry mode
```

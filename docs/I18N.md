# UI strings and translations

Visible chrome lives in [`src/mainview/i18n/en.ts`](../src/mainview/i18n/en.ts) and [`src/mainview/i18n/es.ts`](../src/mainview/i18n/es.ts). Wiring: [`src/mainview/i18n/index.ts`](../src/mainview/i18n/index.ts). Vocabulary: [CONCEPTS.md](./CONCEPTS.md).

Write for the person using Fulvid. Never drop a technical contract (placeholder, escape, example syntax) to make a sentence prettier.

Prefer: correct meaning, correct UI context, natural phrasing, then brevity. English and Spanish should each read as if written for Fulvid. Do not translate word for word. If a string is already natural and accurate, leave it.

## Context

Read the control, the label next to it, and the action it performs. The same idea may need a different shape as a button, tooltip, hint, empty state, error, menu, or statusbar item.

- A Context button that opens Graph is **Show in Graph** / **Ver en el Grafo**, not a fragment like "See where".
- Search finds text in documents. Do not describe it as "Find a document".
- Ctrl+Shift+F toggles **Focus mode**. That is not Graph Focus. F11 (Ctrl+Cmd+F on macOS) toggles native Full Screen.

Hints and tooltips must add information the label does not already give. Settings hints should say what changes, when it applies, what the options mean, and a real example when that helps. Do not start with "This setting controls..." or repeat the label.

Empty states should name the empty thing once. Under **Incoming links**, prefer **No incoming links yet.**

Errors explain what happened, stay calm, and include a next step when one exists. Do not invent causes or leak host paths, errno, or stack traces.

## Syntax that must stay exact

Rewrite the surrounding sentence. Keep these exactly as Fulvid uses them:

```text
[[note]]
[[note|Label]]
[label](note.md)
[label](note.md#heading)
[label](#heading)
#heading
{date}
{count}
{name}
{path}

{to}

Shift+F12
F2

```

Do not translate those examples. Keep `[[note]]` and the English path in `[label](note.md)`.

In TypeScript catalog strings, keep real newlines as `\n`. The UI must not show a literal `\n`.

## The `|` rule (vue-i18n)

vue-i18n treats `|` as a plural separator. An unescaped pipe truncates the message.

To show a wikilink alias, the TypeScript source must use `\\|` so the catalog value still contains `\|`:

```ts
wikilinksHint:
  "Treat [[note]] and [[note\\|Label]] as document links.";
```

```text
TypeScript source:   [[note\\|Label]]
Catalog string:      [[note\|Label]]
Visible UI:          [[note|Label]]
```

`bun run i18n:check` fails on an unescaped `|` in a catalog value. Do not use `|` as a visual separator in messages. Fulvid uses a middle dot in compact summaries for that reason.

If the i18n stack changes, re-check this escape against vue-i18n before editing the rule.

## Placeholders

`{count}`, `{name}`, `{path}`, and the other `{...}` tokens are a contract across locales. Do not rename, translate, or drop them. Word order around a placeholder may change with the language.

`i18n:check` compares placeholder names and counts between catalogs.

## Punctuation

Do not add typographic Unicode just to look editorial. Prefer ASCII `-`, `"`, `'`, `...`, and `>` for menu paths (`View > Focus mode`).

Spanish `á`, `ñ`, `¿`, and `¡` stay. Do not strip legitimate language characters.

Avoid unless there is a consistent, existing reason in the same UI:

```text
en-dash em-dash curly-quotes ellipsis arrows guillemets
```

Also avoid non-breaking spaces, zero-width characters, and decorative symbols in catalog strings.

English: short labels; extra detail in hints. Spanish: neutral contemporary software Spanish, not a calque and not bureaucratic.

## Adding a locale

1. Add `src/mainview/i18n/<language>.ts` with the same key tree as `en.ts`.
2. Register it in `src/mainview/i18n/index.ts` `messages`.
3. Add the locale to `Locale`, `VALID_LOCALES`, and the Settings language select in `SettingsPage.vue`.
4. Run `bun run i18n:check`.

The auditor treats the first locale in sorted order as the structural reference.

## Validation

After changing catalogs or `t(...)` usage, run `bun run i18n:check`. The contributor gate is `bun run validate` ([CONTRIBUTING.md](../CONTRIBUTING.md)).

`i18n:check` blocks on missing/extra keys, type mismatches, placeholder mismatches, unescaped `|`, missing static `t()` keys, and hardcoded `aria-label` / `placeholder` / similar attributes. Dynamic keys are printed for review and do not fail the gate.

Check the changed strings in the running app when you can (Settings hints wrap; Graph and Context empty states sit under headings).
